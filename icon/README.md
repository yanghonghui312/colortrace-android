# colortrace 应用图标（Android）

## 一句话

图标 = **App 主界面本身**：深色画布 + 前后对比分割线 + 亮色拖柄；左冷（原片）右暖
（追色后）。全部是**矢量**，仓库里没有一张图标位图。

## 文件职责（改图标只看这两处）

| 角色 | 文件 | 说明 |
|---|---|---|
| **设计源** | `colortrace-icon.svg` | 108×108 viewBox，含三层 + "启动器实际可见区"预览 + 安全圆参考线。给人看/给人改的 |
| **打包产物** | `../app/src/main/res/drawable/ic_launcher_background.xml`<br>`ic_launcher_foreground.xml`<br>`ic_launcher_monochrome.xml` | VectorDrawable，路径数据与 SVG **逐字对应**（Android 不吃 SVG） |
| 装配 | `../app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml`<br>`ic_launcher_round.xml` | `<adaptive-icon>`：把上面三层挂起来 |
| 声明 | `../app/src/main/AndroidManifest.xml` | `<application android:icon=… android:roundIcon=…>` |

## 为什么一行 PNG 都不用出

本工程 `minSdk = 26`，**自适应图标（API 26+）全设备可用** ⇒ 只需要
`mipmap-anydpi-v26/` 一份 XML，不必再补 `mipmap-mdpi/hdpi/xhdpi/…` 位图。
代价：Launcher 自己栅格化（边缘永远干净）；收益：零二进制资产、改色只改一个十六进制。

## 尺寸口径（v1 就是在这里翻车的，务必按**可见区**想）

- **两层各 108×108dp**；`background` 必须**满幅**（遮罩会裁切，留透明会露底）。
- 外层**每边 18dp**（108−72）是**遮罩/视差区**，随时可能被裁掉。
  ⇒ **启动器只显示内层 72dp**：108 空间里的 52dp 在屏幕上占可见宽度 **~72%**，
  四角会顶到遮罩（v1 实拍就是这么翻车的）。
- **关键图形收在居中 66dp 圆内**（半径 33）——圆形遮罩最狠。
  现取 **方片 48dp**（30..78）+ 圆角 11：对角最远点 `(24−11)·√2+11 = 29.4 < 33` ✓，
  在可见区里占 `48/72 = 67%`（≈ Material 方形键线比例）。
  真机复核：圆形遮罩模拟下四角离安全圆还有余量，不被啃。
- **单色层**（`<monochrome>`，API 33+ 带主题图标）：系统**只取 alpha 并染色** ⇒
  只能单色、不能靠颜色区分，描边/细线在这个尺寸会糊 ⇒ 简化成"两块面板 + 中缝"。
- 圆形设备（`roundIcon`）**不需要另画一套**——遮罩由系统做，给同一份内容即可。

### v1 → v2（2026-10-01，真机实拍后改的两处）

| 项 | v1 | v2 | 为什么 |
|---|---|---|---|
| 方片 | 52dp / 圆角 12 | **48dp / 圆角 11** | 启动器只显示内层 72dp，52dp 实占可见宽 ~72%，四角顶到遮罩 |
| 拖柄 | 12dp + 1.6dp 深色描边 | **10.4dp，无描边** | 亮圆 + 深描边落在二分色交界处太抢，真机上像个"镜头" |
| 分割线 | 2.4dp | 2.2dp | 同上，让位给两侧色块 |

## 验证到哪一步（诚实记录）

- ✅ **真机渲染**：`adb shell am start -a android.settings.APPLICATION_DETAILS_SETTINGS -d
  package:com.colortrace.poc` 截图标页，栅格放大逐像素看过（颜色、圆角、拖柄都对）。
- ✅ **圆形遮罩模拟**：本机是方块遮罩（squircle）；按 72dp 可见区做圆形遮罩模拟，
  四角落在 66dp 安全圆内 —— 换原生风格启动器也不会被啃。
- ⚠️ **单色层没验**：本机 OriginOS 不带主题图标开关，只能静态确认它是合法的
  双路径白色剪影（alpha 遮罩由系统染色）。
